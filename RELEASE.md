# Release Process

Clay ships two artifacts from this repo under a **single version**:

- **Clay Python SDK** — published to PyPI as [`pixxel-clay`](https://pypi.org/project/pixxel-clay/).
- **Clay CLI** — multi-arch Go binaries attached to the GitHub Release.

Every release publishes both, at the same version, from the same git tag. A separate `pixxel-datatypes` package has its own cadence and is not covered here.

## Version source of truth

The version lives in exactly one file: [`python/clay/__version__.py`](python/clay/__version__.py).

- `python/setup.py` reads it to set the PyPI package version.
- `main.go` embeds it via `//go:embed` and exposes it to `clay version` and to generated Dockerfiles.

Do not add a second version string anywhere — bump this file and everything else follows.

## Cutting a release

1. **Bump the version** on a branch. Edit [`python/clay/__version__.py`](python/clay/__version__.py) and set the new value — the file has exactly one line:
   ```python
   __VERSION__ = "1.9.0"
   ```
   Keep the double quotes and the `__VERSION__` name exactly as shown; `setup.py` and the Go `main.go` embed both parse this format.

2. **Update `CHANGELOG.md`** with an entry for the new version (one section covering both SDK and CLI changes).

3. **Open a PR to `main`** with the version bump + changelog entry. Merge after review.

4. **Tag the merge commit and push**:
   ```bash
   git checkout main && git pull
   git tag v1.9.0
   git push origin v1.9.0
   ```

5. **Watch [`.github/workflows/release.yaml`](.github/workflows/release.yaml)** in the Actions tab. It runs three jobs in order:
   | Job | What it does | Fails if |
   |---|---|---|
   | `validate-version` | Confirms the tag's numeric part matches `__version__.py`, and the tagged commit is on `main`. | Version mismatch, or tag points outside `main`. |
   | `release-python-sdk` | Builds `./python` with `python -m build` and uploads to PyPI. | Version already exists on PyPI, or `PYPI_API_TOKEN` is invalid. |
   | `release-cli` | Runs GoReleaser — produces `clay_<OS>_<ARCH>.tar.gz` archives, `checksums.txt`, and a GitHub Release. | Build failure or goreleaser config error. |

   The SDK job runs **before** the CLI job so Dockerfiles generated by the new CLI can resolve `uv pip install pixxel-clay==<version>` immediately.

6. **Verify after it's green**:
   - `uv pip install pixxel-clay==1.9.0` works.
   - The GitHub Release page lists archives for linux/darwin/windows × amd64/arm64 plus `checksums.txt`.
   - Downloaded binary prints the right version: `./clay version` → `1.9.0`.

## Pre-releases

Use PEP 440 pre-release suffixes so both PyPI and GitHub accept the same string. Examples:
- `1.9.0rc1` — release candidate
- `1.9.0a1`, `1.9.0b1` — alpha/beta
- `1.9.0.dev1` — dev snapshot

Bump `__version__.py` and tag the same way:
```bash
git tag v1.9.0rc1 && git push origin v1.9.0rc1
```

PyPI marks pre-releases automatically (they require `uv pip install --pre` or `pip install --pre`). Use pre-releases whenever you change the release pipeline itself to exercise it end-to-end before cutting a stable version.

## Recovering from a failed release

- **`validate-version` failed.** The file and tag disagree. Delete the tag (`git push --delete origin v1.9.0`), fix the file, re-tag.
- **`release-python-sdk` failed because the version already exists on PyPI.** PyPI is immutable — you cannot reuse a version. Bump to the next patch (e.g. `1.9.1`) and re-release.
- **`release-python-sdk` failed mid-upload.** Twine uploads atomically per file; if any file is rejected, the version may be partially uploaded. In practice this is rare — bump to next patch and move on.
- **`release-cli` failed after SDK published.** Fix the Go-side issue, bump patch, re-tag. The stranded SDK version on PyPI is harmless (no CLI generates Dockerfiles that pin it yet).

## Documentation deployment

[`.github/workflows/deploy-docs.yaml`](.github/workflows/deploy-docs.yaml) handles the docs site independently. It is out of scope for this release flow.

## Secrets required

| Secret | Used by | Purpose |
|---|---|---|
| `PYPI_API_TOKEN` | `release-python-sdk` | PyPI upload (scope: `pixxel-clay` project). |
| `GITHUB_TOKEN` | `release-cli` | GoReleaser — creates GitHub Release, uploads archives. Provided automatically. |
